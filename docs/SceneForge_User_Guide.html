01Installation

Drag the received .mzp onto a 3ds Max viewport. The installer verifies every copied file by size and finishes with a check that walks the disk from scratch — if anything is missing it names it, instead of writing “done”.

This release requires 3ds Max 2027. The installer checks the Max version and stops if it does not match — instead of leaving you a full set of files and a panel that will not open.

The three places the files go:

whatwhere
core, panel, columns, scene listenerscripts\SceneForge\
the commands visible in Customizeusermacros\SceneForge.mcr
registration of the menu entryscripts\startup\

Installing is repeatable: on every update the older panel versions are removed once the new ones are safely in place, and the final check requires exactly one panel to be left in the folder.

Uninstalling

(SF_odinst = getFiles ((getDir #userScripts) + "\\SceneForge\\SceneForge_odinstaluj_v*.ms"); sort SF_odinst; if SF_odinst.count > 0 then fileIn SF_odinst[SF_odinst.count] else messageBox "SceneForge is not installed.")

It removes the columns from the native explorer, unregisters the scene listener, releases the core and deletes the files. It does not touch your keyboard assignments or panel preferences — after reinstalling, everything is as it was.

It removes only the files it put there itself — the installer leaves a list of them in the plugin folder. Your own script or note kept in that folder stays untouched, and so does the folder itself; the uninstaller writes down what it left behind and why.

02First run

The panel does not start together with Max. Loading the core costs about a second and is meant to happen when you need it — not on every launch of the program.

  1. Customize → Customize User Interface, category SceneForge.
  2. There are two commands there: SceneForge Outliner and SceneForge - Scene reports. The command names stay in English in both language versions — Max remembers your keyboard assignments by them, so translating them would lose your settings. If you also installed the free Explorer Turbo, its command sits in the same category — that is the third one.
  3. Assign a key to them, put them on a toolbar or into a quad menu.

The entry in the main Max menu appears after restarting the program. That is not an oversight: in Max 2025+ the menu manager arrives only as a notification parameter, at the moment Max rebuilds the menus itself.

The Menu button

The first button on the bar: Menu — every panel command in groups (List and view, Viewport, Layers, Selection, Material, Objects, Reports and rules, Settings and tools), with tooltips and shortcuts on the right. The same as the palette (Ctrl+P), but without typing — the palette only works while the panel has focus, because in Max Ctrl+P is Pan. Next to Health there is a Reportsbutton, and the side bar carries the Reports and Rules icons.

Undo and redo (v105)

Every panel operation that changes the scene is one entry in the 3ds Max undo history: rename (F2, batch, template), hide, freeze, renderability, display properties, colour, material, an object's layer, hierarchy, hiding and freezing a layer, a new layer, renaming a layer, nesting layers, selection sets, merging duplicates, scene rules, Scene Doctor, viewport painting. Measured by a probe on each of these operations: operation → max undo → the scene state returns to the earlier one (30 out of 30), and max redo brings the change back.

03Filter language

The filter field accepts a plain substring, but it also understands a syntax that replaces the Advanced Filterwindow. Conditions are joined with a space (a conjunction), and each of them can be negated with a minus: -hidden:1. Parentheses with a vertical bar mean “or”: (layer:A | layer:B).

type:VRayLight layer:02_* poly:>100k -hidden:1
The field suggests as you type

You do not have to know the tables below by heart. Start typing and you will see the keys; after the colon — the values from this scene, with object counts, so you can see straight away how many objects you will get. A list of classes that are not in the scene would be noise, so we do not show it.

Only the term under the cursoris completed, so the rest of the query stays untouched. A value containing a space is quoted automatically. When there are more matches than the list can hold, the last entry says how many are left — a missing entry never pretends to be a missing layer.

Query history

The hist. button next to the field drops down the recent queries (up to 20, newest on top); a click puts the query into the field. Only queries the core accepted without an error get there — an unclosed parenthesis typed halfway does not. The history is remembered between sessions. The command Select by size… in the palette asks for a condition (e.g. >1000), writes size: into the filter and selects everything that is left.

Category and state chips

Below the filter field there is a row of buttons: Geometry, Shapes, Lights, Cameras, Helpers, Space warps, Bones and Hidden, Frozen, Selected. Category chips combine with “or” (an object has one category), state chips with “and”. They are prepended to the text in the field, so Lights + Hidden + a typed layer:02_* means: hidden lights from those layers. The category chips show the number of objects in the scene. The x button clears every chip and leaves the text. The bar can be switched off in the preferences or from the palette.

Measured

Filtering by class and layer compares indices, not text: 0.05–0.08 ms on a scene of 50 026 objects. The worst case — a text pattern over the names — 4.35 ms, against a frame budget of 16 ms.

The Children, Verts, Size and Path columns travel through a separate core channel and are fetched only when one of them is switched on — a column nobody turned on costs nothing.

About the face count

getPolygonCount reads the top of the modifier stack, not the base mesh. Weighted Normals can turn 102 152 vertices into 400 824 — the Faces column then shows the effect of the stack, and the Mod. column its cause.

Viewport colouring

From the palette: Viewport: colour objects by layer / class / material / face count. The wireframe colour of every object is replaced (faces: a green → red gradient by order of magnitude — a heat map of the scene's weight). This is a change to the scene: a violet bar above the list is there to remind you, and Restore wireframe colours brings back the originals (also when the panel is closed, and through Ctrl+Z).

Scene rules

Scene rules… from the palette: a filter query + an action (hide, freeze, select, as a box, See-Through, renderability, move to a layer). A rule acts on the whole scene, including objects the filter is not showing. Test says how many objects match before you change anything; Run all runs the list one by one. The rules live in a file next to the preferences.

Nesting layers

In the layer list drag a layer onto another layerto nest it underneath; drop it on an empty part of the list to pull it back to the root. Max itself refuses a cycle (a parent under its own child) — the status bar then says how many layers were rejected. The operation can be undone.

Dragging a material

In the by material lens a bucket header can be dragged onto an object row. Dropping it on a row that belongs to the selection assigns the material to the whole selection; on a row outside it — only to that row. The (no material) header dropped onto an object takes its material off. The identity of a material is the object in the bucket, not the name — two materials can share a name. The operation can be undone.

07Scene reports

Ctrl+Shift+R. Four tabs, none of which computes itself when the window opens — scanning a large scene takes time, and a window that freezes Max on opening gets opened once.

Geometry duplicates

Merge ALL walks every group in the table, checks the vertices and merges them into instances — 340 identical chairs become one mesh and 340 instances. A group with different geometry is skipped and named in the summary. Each group is its own undo block.

Groups of objects with an identical signature, sorted descending. Merging into instances first compares the vertex positions and refuses when they differ — two meshes with the same face count and the same dimensions need not be the same mesh.

Scene weight

Faces and objects per layer and per class. The face count is lazy in the snapshot, so the report computes it first — and says how many remain unknown. Counting them as zero would give totals smaller than the truth and looking perfectly reasonable.

Textures

Every bitmap map: what weighs how much, and what is missing. One row per file, not per occurrence — the same map used a hundred times does not take up a hundred places on disk. The size is the file size, not the memory footprint: that depends on compression and mipmaps and cannot be derived from the resolution. A file that is not there has the size ?, not zero.

Snapshot comparison

Remember the baseline stores the state of the whole scene by handle (name, layer, material, class, parent, faces). Compare shows what was added, removed and changed — one difference per row, with CSV export. Show the changed ones in the list writes is:changed into the filter. An audit of “what have I touched since this morning” in a single table.

Timeline

The most recent scene events (added, deleted, structure, name, state) with a time and a name — a ring of 5 000 events. The in the list writes changed:<N m into the filter.

Scene card

A single HTML file with the numbers about the scene: objects, layers, faces, the heaviest layers and classes, scene health, textures, duplicates. To send to somebody who does not have Max. Compute gathers the reports (the duplicate scan takes about 2 s on 50 000 objects), Save HTML… opens the file in a browser.

Naming

Rules in the form name|regular expression, one per line. An object breaks the convention when it matches none of them. A bad pattern shows ERROR instead of pretending that nothing matches — a typo in a pattern would report the whole scene as a deviation, and that would look like a genuine result.

The names found can be fixed in the same window. The fix works by handles, not by view rows: a filtered-out object has no row number, so going through the view would fix 40 names out of 300 and report “40 changed”.

Undo

The whole fix is one Ctrl+Z. On top of that, a CSV file with the old names is written next to the scene before the change — the undo history does not survive saving and closing the scene, but that file does.

08Explorer Turbo

A separate, free tool for the native Max Scene Explorer. It does not require SceneForge and does not carry its code.

  • Suspending the refresh with a single switch, with the state visible on the bar.
  • Four columnsthe native explorer does not have: modifiers, children, instances and a short note on node health.
What is not there, and why

There is no face-count column. Reading it from MAXScript costs 311 µs per object, that is 15.6 ms per 50 visible rows — nearly a whole frame. And that on light primitives, so for real geometry it is a lower bound. A tool meant to cure a sluggish explorer cannot be what makes it sluggish.

What does go in costs, all together, 0.856 ms per 50 visible rows. One thing saves us: Max only asks about the rows you can see — measured at about 50 on opening and zero growth after two seconds of idling.

09Performance

The same operations, the same scene, the same Max session. The minimum of a series, not the average.

operationnative explorerSceneForgeratio
opening and filling92 992 ms101 ms920×
expanding the whole tree3 383 298 ms1 ms>10⁶×
cost of an idle window+0 %+0,9 %a draw
update after adding 1000 objects—4.4–6.3 mssee below

Three things in this table that are easy to read wrong:

  • An idle native explorer costs nothing. The common form of the complaint — “an open explorer slows Max down” — is untrue as stated. The cost sits in filling and rebuilding the list.
  • The last row has no “native” column, and that is the honest answer. Creating 1000 objects costs Max itself 8.7–12.9 s, and the spread between identical runs reaches 47 %. An overhead of a few milliseconds cannot be seen inside that — on either side. So we quote what was measured directly: our own snapshot update.
  • Our “1 ms” is real work. The view grows from 33 812 to 50 026 rows and hands back data from the start, the middle and the end of the list. It is cheap because the view is an array of indices, and only the rows you can see are drawn.

Busy signal

Operations on a large selection can take seconds. From 500 objects up, the panel says in the status bar what it is doing and switches the cursor to the busy one. The threshold was not picked by eye: at 500 objects the slowest of those operations takes 67 ms, which is imperceptible, while at 1000 it is already 214 ms. The signal itself costs 3.4 ms and appears only where you are waiting anyway.

A correction

An earlier version of this page quoted “+111 ms for us against +6 ms for the native one” here, and the sentence “this is where we are slower”. Checking that charge demolished the measurement itself, not the code: both numbers were samples from noise 37 times larger than they were. The method “measure the whole operation and subtract” had no chance of seeing an effect of a few milliseconds.

One exception, a deliberate one

You save layer states yourself, with the command Ctrl+Shift+L. They then go into the Configstream, because a layer state describes this scene and means nothing in another one. It is the only thing the plugin puts into the file — and only when you ask for it.
